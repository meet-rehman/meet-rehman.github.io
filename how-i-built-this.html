How I built this site with AI, for free

I am not a web developer. I built this portfolio together with Claude, an AI assistant. The AI wrote the code. I decided what goes on the site, supplied the work and checked every statement. This is the order I did it in, so you can do the same.

Diese Seite gibt es nur auf Englisch.

Running costZero. No hosting fee, no domain.
TimeA weekend for the website. Cleaning up my projects before that was the longer part.
ToolsGitHub, GitHub Pages, an AI assistant
Reading timeAbout five minutes

Before you start

Collect these first. The AI can only work with what you give it.

  • A free GitHub account
  • An AI assistant that can work with files and code
  • Your CV and a good photo
  • Your project files: code, reports, images, results
  • One decision: who is the site for? Mine is for employers, PhD supervisors and people with a project.

Step 1Fix your projects first, not the website

I wanted to start with the website. That would have been a mistake. A portfolio site only points to your work, so the work has to be ready to be looked at.

For each project I made one GitHub repository with a short page that answers four questions:

  1. What is it, in one sentence?
  2. What did I do, and with which tools?
  3. What worked?
  4. What did not work, and what would I not trust?

The fourth question matters most. A page that also lists the failures is believed. A page with only successes is not.

Example: one of my projects found that a system was filling in values it had not found. I put that in the first lines of the page, not at the bottom.

Step 2Say what you do in one sentence

My first idea was a list of skills. Nobody remembers a list. I wrote one sentence instead and put it at the top:

I solve data fragmentation in regulatory compliance, BIM, 2D/3D and digital twins of the built environment.

Then decide what to leave out. I left out older design work, because it sends visitors in a different direction. It now has its own page, one click away, for those who want it.

Step 3Build the site in a conversation

I did not write a specification. The work went in small rounds:

  1. I describe what I want, in plain words.
  2. The AI builds it and shows me.
  3. I look at it and say what is wrong.
  4. It corrects, and we repeat.

Most of the value came from round three. Things I caught by looking:

  • My portrait was stretched.
  • A photo edit was too strong and no longer looked like me.
  • The German CV ran onto a second page.
  • A new page existed but nobody could find it, because nothing visible linked to it.
  • A drawing was shown without its labels, which were the important part.

None of these are code problems. They are things only you can see, because you know what the result should look like.

Step 4Publish for free

GitHub can host a simple website at no cost. The service is called GitHub Pages. You create one repository with a special name, yourname.github.io, put the site files in it, and the site is online at that address a minute or two later.

I did not buy a domain. The free address works and looks fine on a CV. A domain can be added later without rebuilding anything.

Step 5Make the CV say the same things

After the site, I rebuilt my CV in English and German from the same facts. Same numbers, same dates, same wording for each project. A reader who compares the CV, the site and GitHub should find no differences.

What you must check yourself, always

This is the part I would not skip.

AI will describe your work better than it was. My older profile texts claimed things my projects could not support. We went through every claim and removed or corrected each one that I could not defend in an interview.

Check every number, date and name. If a figure is on the site, you should be able to say where it comes from.

Never publish passwords or keys. In one of my code files we found an access key that I had typed in directly months earlier. I cancelled the key at the provider and removed it before the code went public.

Do not publish what is not yours. Work done for an employer or a client usually belongs to them. The same goes for other people's maps, photos and documents.

Do not publish what you still need to protect. For my thesis system I publish the method, the results and the failures, but not the source code.

If you live in Germany

  • Impressum. A site that is more than purely private needs one, with your name and a postal address.
  • Privacy text. Say who hosts the site and what data is processed.
  • Visitor statistics without cookies. I use a small statistics service that sets no cookies, so the site needs no cookie banner. I see totals, such as countries and pages, and no individual visitors.
  • Fonts. I load the fonts from my own site, not from a third party.

This is what I did, not legal advice. If your site matters for your business, have these texts checked.

What I would do differently

  • Start with the cleanup, and expect it to take longest. The website was the quick part.
  • Give the AI the original files at the start. Several corrections happened only because it first worked from my summaries, and a summary leaves things out.
  • Ask a native speaker to read the second language. I have not done this yet for my German pages.
  • Stop when it is good enough. A portfolio is a means. The time belongs to the applications it was built for.

Questions
